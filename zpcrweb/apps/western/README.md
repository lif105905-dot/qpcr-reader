# Western analysis（重写版）

本机离线的 Western blot / DNA 凝胶作图工具。按 `../wb-app/PRO.md` 从零实现应用层，
只复用上游两个仓库里「与需求无关但已验证」的底层：16-bit TIFF 解码、Marker ladder 数据、
导出编码思路（PNG/PDF/SVG 复用浏览器能力，TIFF/PPTX 自己写）。

## 跑测试

```bash
npm test        # 单元测试（92 项）
npm run e2e     # 8 组端到端（页面行为 / 拖放与平移 / 导出落盘 / 单文件）
npm run verify  # 全部跑一遍
```

E2E 用系统 Chrome（`chromium.launch({channel:'chrome'})`），不下载浏览器。

## 构建与安装

```bash
npm run build   # src/index.html → dist/WesternAnalysis.html（内联成单文件，130 KB）
npm run app     # 打包成 ~/Applications/Western analysis.app
```

App 是 WKWebView 外壳（`app/App.swift`）：加载包内单文件 HTML，导出走 `WKDownload`
落到「下载」文件夹。**不要**把 `loadFileURL` 改成 `web.load(URLRequest(file://))`——
WKWebView 会白屏（踩过）。

## 结构

```
src/core/     纯逻辑，可单测：doc(文档模型) theme transform canvasmath image lanes
              figure ladders marker annotations render(场景) export(编码)
src/ui/       home(首页) editor(三栏) controls(四步) canvasview figureview exporter
src/app.js    把两者接起来：App.doc / App.img / refresh / exportAs
vendor/       tiff.js、wbladders.js（BlotFigure，MIT）、dnaladders.js（GelFigure，MIT 数据）
e2e/          smoke + phase2..6 + bundle
```

场景（`core/render.js` 的 `scene()`）是「所见即所得」的唯一来源：画布预览、SVG 导出、
位图导出都吃同一串 `image|rect|line|text` 指令。

## 已知取舍

- 不做自动识别（不自动分膜、不自动找泳道），全部手动，符合 PRO.md 的定位。
- 定量分析不在主流程（PRO.md 第 1 节）。
- 凝胶模式与 Western blot 共用同一套流程，差别只有 ladder 表与单位（bp / kDa）。

## 成图版式（v3，论文式）

自上而下，和论文里常见的 WB 图一致（不再是 GelFigure 的斜排版式）：

1. **组名**：选中若干泳道填组名 → 组名 + 下划线，画在最上方。
2. **样品名**：水平放在图**上方**（`style.laneNameAngle` 可改 0/30/45）。
3. **条件行**：药名在图框左侧，各道 `− / +`，整行在图片**上方**。
4. **图片**：裁切后的膜/胶，默认带 0.5 pt 外框。
5. **Marker**：刻度在**图框之外**的左侧，数值更靠左、`(kDa)/(bp)` 在数值上方；
   刻度位置由你在图上点的条带 y 坐标决定，不是"点哪里写哪里"。
6. **抗体说明**：图右下角（`style.antibody`，右栏可直接填）。
7. 目标条带 / 区域框 / 侧边括号 / 侧边文字 画在图内。

字号、角度、抗体、编号都在右栏「成图预览」下方那条样式栏里改；
版式计算在 `src/core/figure.js` 的 `layout()`，绘制指令在 `src/core/render.js` 的 `scene()`，
预览与五种导出共用 `FigureView.paintVector()`。


## 成图区里直接编辑（v4）

不用来回切面板，大部分标注操作就在右边的成图上做：

- **分组**：在泳道名那一行按住鼠标**横向拖**过几条泳道 → 松开即生成一组，并弹出输入框填组名（Enter 提交）。
  组名在上方带下划线；点组名可改名。
- **条件行**：右侧样式栏点「＋ 条件行」，图上方多出一行；点药名格子填药物名（如 `4OHT`）。
  每个泳道初始是 `·`（无处理），点一下变 `−`，再点变 `+`，再点回到 `·`。
- **Marker**：左侧下拉直接选第几道是 marker（选完立刻生效，不需要再点图）——成图里那道显示 `M`，处理区那道虚线变黄；
  再选型号、**勾选要标哪几条**——勾几条就标几条，刻度会自动等距铺在这条泳道里。
  位置不对就**直接按住图上的粉色刻度拖动**对齐条带；「刻度重新等距」可一键复位。没勾就不画刻度。
- 以上任何改动都立刻反映到成图预览和五种导出。

## 打开图片的两条路（原生壳）

- **页面里的「打开图片 / 选择文件」按钮**：调用原生桥 `messageHandlers.pickFile` → 壳子弹 `NSOpenPanel` → 把文件内容以 `File` 注入页面。**不能只依赖 `<input type=file>`**：WKWebView 必须实现 `WKUIDelegate.runOpenPanelWith`，否则点按钮毫无反应（这就是 v2.1 之前"没响应"的原因）。
- **菜单「文件 → 打开图片…」（⌘O）**：不经过网页，直接原生面板 + 注入，作为永远可用的兜底。
- 拖拽图片到窗口同样可用（不依赖上面两条）。

### Marker 面板（v5）

第 3 步按参考样式重做：
- 卡片：`孔 N`、`吻合 NN%`、⭐（记住型号）、×（清空勾选）。
- `所在泳道`（`N · M`）与 `型号` 两个下拉，选完即时生效。
- 「按条带重新对位」：读处理区该道的像素列，把每条刻度吸附到最近条带中心并给出吻合度；「刻度重新等距」退回等距。
- `条带（显示 k/n）` 可折叠，每条带带 `已选 / 未选 / 已对上` 徽章。
- `自定义 Ladder`：填名称与分子量列表即保存到本机（localStorage，键 `wa-custom-ladders`）。
- `备份 Marker 库` 导出 `marker-ladders.json`，`导入 Marker 库` 合并回来。

### 图像面板（v6）

第 1 步按参考样式重做，面板里的东西都是真数据：
- `胶的类型`：只显示当前工作区固定的类型（WB → 蛋白胶 kDa；凝胶 → DNA 胶 bp），不做切换——两个工作区已经分开了。
- `图像显示`：灰度（保留原色置灰，因为解码就是灰度）。
- `反色`、`当前成图：白底黑带` 提示。
- `旋转`：滑块 + 数字框；`自动转正` 用行投影方差在 ±8°（0.5° 步进）里找最佳角度，`回到自动角度` 退回。
- `参考网格`、`左转/右转 90°`、`水平/垂直翻转`（翻转烘焙进旋转画布，预览与五种导出一致）。
- `暗部/亮部`：按分位百分比定黑白场（替代旧的亮度/对比度），配 64 级直方图。
- `相机过曝 / 色阶削顶`：对原始信号的 0/1 两端统计。
- `标红过曝像素`：按显示画布缓存蒙版，把 ≥254 的像素标红。
- `Gamma`：0.4–2.5，参与 LUT。

### 成图版式（v7，对齐论文图）

自上而下：**上级组名**（横跨全图的线，样式栏「上级组」填）→ **组名**（每组的短线，组与组之间留缝）→ **条件行**（4OHT −/+）→ **样品名**（泳道名，太长会自动缩字号）→ 图片（Marker 数值在框外左侧）。

- 泳道名可在成图里**单击就地改名**（拖动仍是框选分组）。

### 标注（v8）

第 4 步改成六张卡片（对齐参考模板），点卡片选工具，操作都在**成图区**完成：

| 卡片 | 操作 |
|---|---|
| 分组横线 | 在泳道名上一拖即分组，松开填组名（线两端自动留缝） |
| 目标条带 | 点一下条带，自动读出该处的分子量当标签 |
| 条件行 | 点卡片即加一行，再点药名格子输药名、点各道格子循环 `· → − → +` |
| 区域框 | 在图上按住拖一个框 |
| 侧边括号 | 在左侧按住上下拖一段 |
| 侧边文字 | 点图中位置，输入文字 |

工具是一次性的：用一次自动收起，避免误点继续加标注；卡片再点一次可手动取消。

### 投稿级导出（v9）

按最严格的期刊要求补齐：

| 导出 | 说明 |
|---|---|
| **投稿包** `*_submission.zip` | 一次拿到全部材料：600 dpi 无损 TIFF + 真矢量 PDF + 全矢量 SVG + **原始未裁剪图** + 处理日志 JSON + README 检查清单 |
| PDF | **真矢量**：文字/线/刻度是 PDF 指令（Helvetica base-14），只有图块是内嵌位图；放大不毛 |
| TIFF | 无损 8-bit 灰阶，默认 600 dpi |
| SVG | 全矢量，AI / Inkscape 可直接改字 |

尺寸与分辨率：右上「宽度」预设 85 / 89 / 114 / 174 / 183 mm，「分辨率」300 / 600 / 1200 dpi。

**投稿检查**（右上常驻，实时）：字号 <5 pt 报错、<7 pt 提示；边框线宽 <0.25 pt 报错；dpi <300 报错、<600 提示；不是常见栏宽提示；没写抗体说明提示。

### 侧边文字（v11）

- 点第 4 步的「侧边文字」卡片，**立刻**在成图区弹属性卡并新建一条，不用再去图上点一次。
- 加好的文字可以**直接按住左右拖**，位置被夹在图片宽度内（0–100%），拖不出去。
- 点文字再次打开属性卡；属性卡里有文字、位置（胶图下方/上方/图左/图右）、左右位置滑块、字号（留空跟随全局）、颜色、删除/完成。
- 图下方同时有抗体说明时，文字会自动排到抗体说明的下一行，不重叠。

### 侧边文字（v10 历史）

成图区里直接编辑：点已有文字（或用「T」卡片新建）弹属性卡，包含文字内容、位置（胶图下方/上方/图左/图右）、左右位置滑块（0–100%）、字号（留空跟随全局）、颜色（默认/黑/白/深红/深蓝），以及删除 / 完成。

- 文字按「位置」贴在图框四周，滑块控制沿边位置，可用来避开 Marker 数值。
- 每条文字可以有自己的字号与颜色；留空即跟随全局字号。

### 分组可以嵌套（v13）

同一批泳道可以有多层组，横线永远不会叠在一起。规则是「一行里不能有两根相交的线」：

- 跨度大的组先占上面的行；后面的组只要和已排好的组**泳道范围相交**，就自动往下让一行。
- 因此 1–2 ⊂ 1–4 ⊂ 1–8 ⊂ 全部 会形成阶梯；互不相交的组（比如右边 9–10）会回到最上面一行，不留空行。
- 完全相同的泳道不会被重复添加（重新拖同一段是改名字）；如果确实需要两行，把范围拖成差一道的重叠区间即可。
- 层级是渲染时算的，不写进数据；删掉某一层，其余自动收拢。

### 布局细节（v13，对齐 GelFigure）

右栏样式条：

- **组线端点**：组名横线两端加小竖脚（GelFigure 的 `groupTicks`）。
- **样品名在条件行上方**：默认开（GelFigure 的 `laneNamesAboveConditions`），关掉则条件行回到上方。
- **分组文字**：放不下时 `放不下折行`（默认）/ `缩小字号`（到最小字号为止）/ `不处理`（溢出）。
- **最小字号**：缩字时的下限，默认 5 pt。
- **面板字母**：成图左上角的 A/B/C，投稿多面板图时用。

分组分层与折行都照 GelFigure 的 `groupTiers` / `wrapText` 实现（含「按线 + 文字外延判重叠」「窄组贴近胶图」「中文逐字断行」）。

### 撤销/重做与项目文件（v14）

- **打开项目**（⌘O）：恢复文档并把图片重新解码；文件不对会明确报错。

### 泳道细节（v16）

### 多 marker 孔（v17）

一张图可以有多孔 ladder（例如同一张膜左右各有一道预染 marker，或长胶分两段）。

- 第 3 步顶部「孔 1 / 孔 2 …」切换当前编辑的孔，右侧「＋ 加一孔」「删本孔」。
- 每孔独立：所在泳道、型号、勾选的条带、刻度位置。
- 成图里**第 1 孔画在框外左侧**（数值在图外），其余孔画在各自泳道中线处（数值贴在图内、白字黑描边）。
- 该泳道在成图里显示为 `M`。

另加「原图」导出：把打开时的原始文件（未裁剪、未调色）原样导出，用于投稿附「原始全膜图」。

### 自动识别（v19）

第 2 步「自动识别泳道（导入时）」默认开启：导入图片后自动判断明暗、估转正角度、找出泳道中线。

- 引擎直接移植自 GelFigure 的 `js/engine.js`（MIT），放在 `vendor/gf-engine.js`，只做识别用。
- 识别不准：可在图上拖泳道线；或直接改「条数」（自动切换为手动）；点「重新识别」重跑。
- 识别结果就是普通数据（`laneCount` / `laneCenters` / `view.rotate`），没有隐藏的“识别态”。

### 导出尺寸与粘贴到 PPT（v21）

- **TIFF**：写入正确的 X/Y 分辨率（`282/283` 为 RATIONAL，`296=2` inch），物理尺寸 = 像素 / 导出分辨率。
  之前 XResolution 写成了 0、且没有 YResolution，看图软件会自己猜 dp​i，结果贴进 PowerPoint 又小又变形。
- **PNG**：像素数不变，但写 300 dpi 的 `pHYs`，所以 85 mm 单栏图贴进 PPT 约 17 cm 宽（以前按 72 dpi 换算，尺寸忽大忽小）。
- 要更细的印刷级 TIFF，把「分辨率」选 600/1200 dpi；要贴 PPT 更大，把「宽度」选 174 mm 双栏。

### 暂存面板（v22）

同一张图要出多块成图时，用成图区下方的「暂存」区：

1. 右栏「文件名」先填好（这就是这块面板导出时的名字），处理完一个区域点**暂存当前**；
2. 暂存后当前编辑区自动重置（图片保留），继续裁下一个区域；
3. 点暂存项的缩略图/「编辑」= 回到那块继续改，改完自动回写；
4. 勾选若干项 → **导出选中**（选 PNG/TIFF/PDF/SVG）：1 张直接下载，多张打包成 `figures_N.zip`，包内文件名用面板名；
5. 条目多了列表限高 260px、自动滚动叠放，名字始终可见；点条目会展开大图并切到编辑。

### 布局调整（v23）

- 「成图样式」（字号 / 泳道名字号 / Marker 字号 / 角度 / 上级组 / 抗体 / 编号 / 组线端点 / 样品名在条件行上方 / 分组文字 / 最小字号 / 面板字母 / ＋条件行）从右下角搬到**左栏最下方**，归到「成图样式」一张卡。
- 暂存区紧跟成图画布下方，不再被顶到右栏底部；成图画布高度改为按窗口高度自适应（上限 560pt），下方留白放到暂存之后。
- 条件行与泳道名的行距照 GelFigure 的算法放宽：条件行按 `1.35 em` 堆叠，泳道名与条件行之间再留 `1.15 em`（原来几乎贴在一起）。

### 条件行排版（v24，照抄 GelFigure 的 render.js）

- **行距**：每行的基线间距 = 该行字号 × 1.3（GelFigure 的 `yTop -= cp * 1.3`），行字号可以在左栏「标注」列表里单独填（留空 = 跟随全局）。两行不同字号时，块高就是各自 1.3 倍之和。
- **多行压缩**：因为行距跟着行字号走，6 pt 的行自然比 9 pt 的行更紧；不再用「全局字号 × 固定系数」一刀切。
- **药名对齐**：药物名右对齐到与 Marker 数值**同一条竖线**（`layout.axis.labelX`），左边距按「最宽的数值/单位/药名 + 文字↔刻度↔图框两段等宽间隙」自动计算，长药名不会被裁掉。
- **顺序**：默认「组名 → 样品名 → 条件行 → 图」；关掉「样品名在条件行上方」后，条件行整体移到名字上方（GelFigure 的 `laneNamesAboveConditions`）。

### 导出与暂存（v25）

- 成图区只剩 **PNG / SVG / TIFF / 原图** 四个按钮（PDF 与投稿包已按你的要求从界面撤掉；PDF 管线仍在，需要时用 `WA.exporters.run(app, 'pdf')`）。
- **文件名**现在是「面板名」：输入名字 → 点「暂存当前」，右上列表就显示这个名字；暂存后面板重置、文件名自动清空，为下一个区域准备。
- 连续暂存多张时，列表按右栏剩余高度自动伸缩并自己滚动，不会再被下边缘截断。

### 换图 / 清空处理区 / 每条泳道单独样式（v26）

- **换图不再覆盖上一张**：拖进新图会被当成「新面板」——正在编辑的那张若已暂存，会先存回再脱离。之前的 bug 是换图后仍停留在「编辑暂存项」状态，`refresh()` 把新图写回了上一张面板。
- **清空处理区**（图片处理区标题栏右侧）：只清掉当前没暂存的工作区（图片、裁切、泳道、标注），下面的暂存一张不动；清空后拖新图不会影响已有面板，已暂存的面板仍可点「编辑」返回修改。
- **每条泳道单独样式**：在成图区点任意泳道名 → 属性卡里改文字、字号（留空 = 跟随全局）、字体（10 种系统字体）、颜色；回车提交并跳到下一道，方便一条条往下填。只影响这一道，其它道保持全局样式；导出 PNG/TIFF/PDF/SVG 都按各自的字号字体颜色画。
